# 실행 에이전트 계약

설계 에이전트(이 스킬)와 실행 에이전트는 메시지가 아니라 파일로만 연결된다. 실행 쪽 CLI는 Claude Code든 Codex든 상관없다. 프로젝트의 `AGENTS.md`에 아래 블록이 있으면 이 계약을 따른다.

| 파일 | 쓰는 쪽 | 읽는 쪽 |
| --- | --- | --- |
| `docs/purpose/` | 설계 에이전트 (사용자 확정 후) | 실행 에이전트 |
| `docs/worklog.md` | 실행 에이전트 (추가만) | 설계 에이전트 (변경 검토 때) |

## 운영 흐름

사용자가 두 에이전트 사이를 직접 지휘한다.

1. 설계 에이전트와 논의하고 구조를 확정해 `docs/purpose/`에 반영한다.
2. `docs/purpose/` 변경을 커밋한다. 실행 에이전트가 다른 worktree나 브랜치에서 일하면 그 브랜치가 이 커밋을 포함해야 한다.
3. 실행 에이전트에게 `T-xx` 단위로 지시한다. 예: `T-03 진행해`.
4. 실행 에이전트는 구현·검증 후 `docs/worklog.md`에 기록을 추가한다.
5. 실행 쪽 변경이 병합되면 설계 에이전트에게 변경 검토를 요청한다.

## AGENTS.md 블록

프로젝트 루트 `AGENTS.md`에 넣는다. Claude Code는 `CLAUDE.md`에 `@AGENTS.md` 한 줄을 두어 같은 내용을 읽게 한다. 규칙을 두 파일에 복사하지 않는다.

```markdown
## 설계 문서와 Worklog

- 설계 기준은 `docs/purpose/`다. 작업 전 `overview.md`에서 해당 작업(T-xx)의 상위 목적과 완료·검증 기준을 확인한다.
- `docs/purpose/`는 수정하지 않는다. 목적·범위·완료 기준에 문제가 보이면 Worklog의 `설계 피드백`에 남긴다. 그 문제 때문에 계속 진행할 수 없으면 멈추고 사용자에게 묻는다.
- 완료 기준을 바꾸거나 낮춰서 완료로 처리하지 않는다.
- 작업을 끝낼 때마다 `docs/worklog.md` 끝에 기록을 추가한다. 기존 기록은 수정하지 않는다.
- T-xx에 해당하지 않는 작업은 `무관`으로 기록하고 이유를 쓴다.
- 실행하지 않은 검증은 결과로 쓰지 않고 `미실행`으로 표시한다.
```

## Worklog 양식

상위 목적은 `overview.md`에서 T-xx로 찾을 수 있으므로 다시 쓰지 않는다.

```markdown
## T-03 마감 전 수동 공지 (YYYY-MM-DD) — 완료
- 브랜치/커밋: …
- 변경 범위: …
- 계획과 달라진 점: … (없으면 "없음")
- 검증: <완료 기준> → <실제 결과> [충족 | 미충족 | 미실행]
- 남은 불확실성·후속: …
- 설계 피드백: … (없으면 "없음")
```

- 제목의 상태: `완료` · `부분 완료` · `중단`
- T-xx가 없는 작업은 제목을 `## 무관: <작업> (YYYY-MM-DD)`로 쓰고 `변경 범위` 아래에 `무관 사유`를 추가한다.
