# docs/purpose/ 양식

ID 규칙은 모든 파일에서 같게 쓴다. 한 번 붙인 ID는 바꾸거나 재사용하지 않는다. 제외한 항목도 ID를 유지하고 상태만 바꾼다.

| 대상 | 형식 | 예 |
| --- | --- | --- |
| 대목적 | `P0` | `P0` |
| 중목적 | `P<n>` | `P1`, `P2` |
| 소목적 | `P<n>.<m>` | `P1.1`, `P2.3` |
| 구현/작업 | `T-<nn>` | `T-01` |
| 마일스톤 | `M<n>` | `M1` |
| 결정 | `D-<nn>` | `D-01` |
| 판단 규칙 | `GR-<nn>` | `GR-01` |

목적 상태: `확정` · `미결` · `보류` · `제외`

실행 에이전트의 Worklog는 `T-xx`를 참조하므로 작업 결과에서 목적까지 거꾸로 추적할 수 있다. Worklog 양식은 [worklog-contract.md](worklog-contract.md)에 있다.

---

## overview.md

```markdown
# <프로젝트명>

## 대목적
P0: <누가> <어떤 문제를 해결해> <어떤 결과를 낸다>.

- 제약: …
- 비목표: …
- 성공 기준: … (잠정이면 측정 방법과 함께 `잠정`으로 표시)

## 목적 계층
- P1 <중목적> — 이유: … / 달성 결과: … [확정]
  - P1.1 <소목적> — 이유: … / 달성 결과: … [확정]
  - P1.2 <소목적> — … [미결]
- P2 <중목적> — … [확정]

## 구현 연결표
| ID | 구현/작업 | 상위 목적 | 문제·근거 | 단순 대안·선택 이유 | 범위·비용·의존성 | 완료·검증 기준 |
| --- | --- | --- | --- | --- | --- | --- |
| T-01 | … | P1.1 (+P2.1) | … | … | … | … |

## 마일스톤
| ID | 범위 | 확인할 핵심 가정 | 종료 기준 |
| --- | --- | --- | --- |
| M1 | T-01, T-02 | … | … |

## 보류·제외
| ID | 상태 | 이유 | 재검토 조건 |
| --- | --- | --- | --- |

## 미결·가정
- [가정] … → 확인 방법: …
- [미결] … → 결정할 사람/시점: …
```

작성 규칙:
- `상위 목적`에는 주된 목적을 먼저 쓰고, 추가로 지원하는 목적은 괄호에 `+`로 붙인다.
- `문제·근거`에는 관측 사실과 가정을 구분한다. 가정이면 `(가정)`을 붙인다.
- `완료·검증 기준`은 계획이다. 실제 결과는 Worklog에만 쓴다.

---

## golden-rule.md

프로젝트가 끝날 때까지 반복 적용할 판단 규칙만 둔다. 일회성 결정은 `decisions.md`에 둔다.

```markdown
# Golden Rule

- GR-01 <규칙> — 이유: … / 적용 범위: … / 출처: D-xx
```

---

## decisions.md

추가만 한다. 결정을 뒤집을 때는 기존 항목을 고치지 않고 새 항목에서 `대체: D-xx`로 참조한다.

```markdown
# 결정 기록

## D-01 <결정 한 줄> (YYYY-MM-DD)
- 관련: P1.1, T-01
- 이유·근거: …
- 검토한 대안: …
- 영향: …
- 재검토 조건: …
```
